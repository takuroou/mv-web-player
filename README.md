# MV Pocket — MV Web Player

OneDrive などに保存したスマホ用ゲーム ZIP を iPhone に取り込み、Safari／ホーム画面から遊ぶための Web プレイヤーです。取り込んだゲームとセーブは端末内に保存します。プレイヤーにゲームをアップロードする API はありません。

このフォルダーにはプレイヤーのソースだけを置きます。RPGツクールMVの実行素材、開発中のゲーム、ゲーム ZIP、セーブのバックアップは含めません。GitHub Pages にプレイヤーを公開した後も、ゲーム本体の更新は OneDrive の ZIP を取り込む操作で行います。

## 1. GitHub Pages に配置する

この手順はまだ実行されていません。リポジトリの作成・コードのアップロード・公開は利用者が行ってください。すでに公開された URL はありません。

1. GitHub でプレイヤー専用のリポジトリ（例：`mv-web-player`）を作成します。GitHub Free を使う場合は **Public** を選びます。親フォルダーの `m_mv` 全体や `MV-Portable-Editor` をアップロードしないでください。
2. **この `MV-Web-Player` フォルダーの中身だけ**をリポジトリのルートに入れ、`main` ブランチへコミットします。`index.html` がリポジトリ直下になる構成です。隠しフォルダー `.github`、`.gitignore`、`.nojekyll` も必要です。ブラウザーのファイル追加で隠しファイルが抜ける場合は GitHub Desktop または Git を使ってください。
3. リポジトリの **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
4. **Actions → Publish player to GitHub Pages → Run workflow** から `main` を実行します。以降は `main` の更新でも自動公開されます。
5. 実行が成功したら **Settings → Pages → Visit site** の HTTPS URL を開きます。通常は `https://アカウント名.github.io/mv-web-player/` です。

既存のリポジトリにゲームを含めてしまうと、Pages の公開が止まっても GitHub のソースからゲームが見えてしまいます。**公開リポジトリへのアップロード前に、プレイヤーのファイルだけであることを確認してください。** `.gitignore` は誤追加を減らす補助であり、既に追跡されているファイルや強制追加は防げません。

公式資料：[GitHub Pages の作成](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)、[GitHub Actions による Pages 公開](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。無料公開リポジトリと標準 Actions ランナーを使う構成です。独自ドメインは不要です。

## 2. iPhone でゲームを取り込む

1. 初回はインターネットにつながった状態で、上記の URL を **Safari** で開きます。
2. Safari の共有メニューから **ホーム画面に追加**し、追加したアイコンからプレイヤーを開きます。Safari とホーム画面版を行き来するより、普段使う方を決めてから取り込むことを推奨します。
3. これまでどおり、このチャットでスマホ用の **1P ビルド**を依頼し、OneDrive の同期完了を待ちます。
4. iPhone の「ファイル」アプリで OneDrive を利用できる状態にし、ゲーム ZIP を取得します。必要なら OneDrive 側から「ファイル」に保存してください。ZIP を手動で展開する必要はありません。
5. プレイヤーの **「ZIPを選ぶ」** から、その ZIP ファイルを選びます。取り込み中は画面を開いたままにし、端末の空き容量を確保してください。
6. 取り込み完了後にゲームを起動します。音声開始の操作が表示された場合は画面をタップしてください。
7. 一度終了してから、機内モードでもホーム画面のアイコンから起動できることを確認します。

ゲーム ZIP の選択は、iPhone 内のファイルをプレイヤーが読む操作です。標準のプレイヤー実装は、そのファイルを GitHub や別のサーバーに送信しません。取り込んだゲーム内の JavaScript も実行されるため、自分で用意したゲームのみ取り込んでください。外部サーバーとの通信や外部素材を必要とするプラグインは、このプレイヤーの制限により動作しない場合があります。

## 対応するゲーム

- このエディターのスマホ用ビルドで作成した **`format: 1`** の ZIP が対象です。`mobile-build.json` と `mobile-manifest.json` を検証し、ファイルの欠落・改変・不正なパスを検出します。
- 現在の 1P 用ビルドのタッチ操作、音声開始、エラー表示をそのまま使います。
- 一般の配布用 ZIP、暗号化済みゲーム、RPGツクールMZ、Windows 専用プラグイン、QuestPlay 独自形式を直接動かす汎用プレイヤーではありません。
- QuestPlay のセーブを自動で移すことはできません。互換性も保証していません。このプレイヤーで作成したセーブの書き出し・復元を利用してください。
- iPhone 実機でのゲーム全体の動作は、利用者の環境で確認が必要です。最初に「かばん」「製作」「音声」「ゲーム内セーブ／ロード」「機内モードでの再起動」を試してください。

## 更新、前の版への切り替え、セーブの保管

同じゲーム ID の新しい ZIP を取り込むと、ゲームを更新できます。ゲーム ID はビルド設定で決まり、ファイル名を変えるだけでは別ゲームになりません。更新途中で失敗した場合も、完了済みの版を残す構成です。各ゲームの **「更新・セーブ・管理」→「前の版に戻す」** から、保存されている前の版へ切り替えられます。

ゲームの版を戻しても、セーブの内容までは自動で巻き戻りません。ゲームの更新でデータ構成やプラグインを変えた場合、古い版と新しいセーブが互換にならないことがあります。更新前にセーブを書き出してください。

セーブのバックアップは **「更新・セーブ・管理」→「セーブを書き出す」→「ファイルに保存」** で保存します。iPhone では **「共有する」** から OneDrive や「ファイル」に渡すこともできます。別の iPhone では同じゲームを取り込んでから **「セーブを読み込む」** で復元します。復元は現在のセーブに影響するため、画面の対象ゲームを確認してください。GitHub Pages はセーブをクラウド同期しません。**「ゲームを削除」** はゲーム本体と前の版だけを削除し、セーブは残します。同じゲーム ID の ZIP を再び取り込むと、そのセーブを使えます。

iPhone の空き容量不足、Web サイトデータの削除、ホーム画面アプリの削除等で端末内データが失われる場合があります。永続保存の要求が成功してもバックアップの代わりにはなりません。重要なセーブは定期的に OneDrive へ書き出してください。URL のドメインを変えると端末内データは引き継がれないため、移転前にも書き出しが必要です。

プレイヤー自身を更新する場合は、このフォルダーのコードを公開リポジトリへ反映します。ゲームを閉じてプレイヤーをオンラインで開き直し、更新が案内されたら反映してください。データがある端末で、更新のために Safari のサイトデータを消す必要はありません。

## 公開するファイルの制限

`.github/scripts/prepare-pages.cjs` が公開ファイルを明示的に選び、`_site` にコピーします。ワークフローは `_site` だけを Pages に渡します。

公開対象は HTML、CSS、プレイヤーの JavaScript／ES Modules、Web アプリのマニフェストとアイコン、空の `.nojekyll` だけです。README とワークフロー等は Pages のファイルには含めません。ただし、公開リポジトリのソースとしては閲覧可能です。

ZIP、セーブ JSON、ゲーム素材、`play`／`data`／`img`／`audio` などのフォルダー、不明なファイル、シンボリックリンクが混じると公開処理を停止します。エラーが出た際はゲームを OneDrive 等へ移し、リポジトリ側の公開状態も確認してください。安易にチェックを外して公開しないでください。

プレイヤーにファイルを追加する開発時は、`prepare-pages.cjs` の `PUBLIC_FILES` と `sw-core.mjs` の `SHELL_FILES` を併せて更新します。**コードを更新して再公開する際は、`sw-core.mjs` の `SHELL_VERSION` を必ず新しい値へ増やしてください。** オフライン用キャッシュを版ごとに分け、利用中の旧プレイヤーのファイルを新しいファイルで上書きしないために必要です。

`_site` は生成物なのでリポジトリに追加しません。ローカルで同じチェックを再実行する場合は、前に生成した `_site` をこのフォルダーの外へ移してから実行してください。`node .github/scripts/prepare-pages.cjs 外部の新しい出力先` とすると、最初からこのフォルダーの外へ出力することもできます。既存の出力先は上書きしません。

## 開発者向けローカル確認

親フォルダーから、エディターに同梱した Node.js で次を実行できます。

```powershell
.\MV-Portable-Editor\runtime\node.exe .\MV-Portable-Editor\tests\qa-web-player.cjs
```

表示された `http://127.0.0.1:ポート/` を PC のブラウザーで開きます。このテストサーバーはプレイヤーの許可ファイルだけを配信します。ゲームプロジェクト、ゲーム ZIP、エディターの API は配信しません。GitHub Pages のサブディレクトリー構成を確認する場合は、起動前に `$env:WEB_PLAYER_BASE = '/mv-player/'` を設定します。

`file://` で HTML を直接開いても動きません。Service Worker を使うため、公開時は HTTPS、PC でのローカル検証は localhost が必要です。iPhone から PC の HTTP URL を開く構成は、このプレイヤーの本来の使い方ではありません。
